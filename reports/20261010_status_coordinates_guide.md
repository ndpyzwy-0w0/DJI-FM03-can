# 状态显示与坐标记录实验版 v1

这一版已经把校准阶段、原始坐标、边界候选和 A/B 记录加到固件与两套上位机。仅增加观察/记录，没有新增自动校准、位置回拉或自动运动命令。软件与编译验证已完成，尚未把新固件烧到开发板，也没有开展新的硬件实验。

## 第一轮推荐：浏览器上位机＋现有监听固件

浏览器版直接解析原始 CAN 帧，**兼容板上上次恢复的 listen_1m，不需要为了查看坐标先重新烧录**。新版服务已在 `http://127.0.0.1:8765` 启动，初始 idle，串口关闭。当前真实串口号要在页面刷新核实，不能照抄历史 COM17。

1. 双击项目根目录 `启动上位机.cmd`，或打开上面的本机网址。应出现“电机状态与坐标”面板。
2. 按已有监听接线接好 RS3 与 FM03，选择当前适配器串口和“校准”场景，点击“开始抓包”。先由用户检查并记录灯色及常亮/闪烁、两端电源、RS3 前置拨轮设置、监听模块 Rs=3.3V、同一时刻仅一块模块接总线。
3. 用 **RS3 自己的菜单**进行行程标定。上位机只显示原始阶段 0/1/2/3；阶段 1/2 不指定某端或某次碰撞，阶段 3 标为“校准后工作阶段候选”。未校准阶段和哨兵值不显示成有效坐标。
4. 校准后用 RS3 拨轮前进、停住，观察坐标；点击“记录 A”。换到另一个位置停住，点击“记录 B”。显示 B−A 的原始坐标差，**点击记录按钮不会让电机运动**。
5. 可以观察已有虚拟边界；坐标为 0/4096 时显示边界坐标，在持续向外非零速度、连续边界样本和新鲜数据同现时提示虚拟限位候选。不要把提示当通用堵转报警。
6. 点击“停止并保存”。原始 `.log` 和本次摘要 `.json` 自动保存；有 A/B 时还会生成同名 **`.coordinates.json`**，第一次记录就保存，结束时更新为会话已结束。页面有“下载坐标记录”。

例：`20261010_..._calibration.log`、`20261010_..._calibration.json`、`20261010_..._calibration.coordinates.json`。后者是新衍生文件，不是电机原始数据，不覆盖任何旧 log/json。

记录包含 A/B 原始值、阶段、接收段、设备采样时间、点击记录的北京时间、有效性和失效原因；重复记录 A/B 会更新当前显示，并保留本次记录历史。原始日志仍保留完整坐标流，面板缓存最多最近 600 个坐标样本，不把缓存当作完整历史。

坐标在主机超过 500ms 未更新，或相对最近设备帧已超过 500ms，按钮禁用；重新校准、序号缺口、适配器重启、驱动/输出丢帧计数变化、串口中断或采集结束使已有 A/B 失效。**失效指不能继续作为当前会话依据，记录的值和时刻仍保留供离线对照。** 百分比仅用当前已观察的 0～4096 范围计算，不能当角度、毫米或编码器分辨率。

## 独立运动控制上位机

双击根目录 `启动运动控制.cmd`，启动已打包的 `dist/FM03_MotorControl_Status.exe`；也可直接运行 `tools/motor_control.py`。程序启动不自动连接串口或 ARM。

- 先关闭浏览器抓包占用的串口，再连接。要使用已有主动运动功能，仍必须遵守原来独立台架要求：RS3 数据线物理脱离总线，只保留电机与收发模块；不要在 RS3 通话总线上 ARM。
- 新版 motor_control 固件的 UART 会输出 `# MOTOR ...`；程序显示阶段、坐标和原始范围百分比。版本应为 `motor_control 1.1 status_coordinates`。旧 motor_control 固件没有这个新状态输出，只会等待，不能把控制下发值误作位置。
- “记录 A/B”只在当前阶段 3、新鲜有效坐标时开放。桌面版记录暂存在程序内，**退出前点击“导出坐标记录”**保存 JSON；导出也不会发送串口/CAN命令。
- 原有速度、定时、脉冲、STOP 和看门狗操作仍在。新功能没有添加回拉 A/B、取消校准或目标位置控制；普通速度 STOP 不能保证中止内部标定。

## 固件与本地交付文件

`src/motor_status.h` 是两种固件共用的只读重组器：完整 CAN 帧拼接、CRC8/CRC16 校验，只接受 0x504/BF→E5/flags00/04:2F/09 00 的 28 字节布局，输出阶段及 int32LE 坐标。续片中的 55 不提前截断包。只解析已知布局，未知布局忽略；有限缓存和超过300ms的半包间隔会断开该包。

- 监听固件：`.pio/build/listen_1m/firmware.bin`，新增 `# MOTOR_CONFIG version=status_coordinates_1` 和 `# MOTOR`，原始帧行格式不变，没有 CAN 发送调用。
- 控制固件：`.pio/build/motor_control/firmware.bin`，新增接收解析和 `# MOTOR`，接收轮询与驱动生命周期在同一 loop，无并发重装驱动调用；发送队列继续为 0、保留每片发送前的空闲检查。
- 稳定交付副本：`dist/FM03_Status_20261010/listen_1m_application.bin` 和 `motor_control_application.bin`。这些是**应用分区镜像**，使用下面 PlatformIO 上传流程匹配引导器/分区表，不能当完整 flash 镜像从地址 0 写入。
- Windows 程序：`dist/FM03_MotorControl_Status.exe`。编译产物仅本机保存、不纳入 Git；源码、实验说明、校验清单和界面测试截图纳入 Git。

如需新固件，在用户确认当前设备和没有抓包占用串口后，用当前串口替换 `<当前串口>`：

```powershell
.\.venv\Scripts\pio.exe run -e listen_1m -t upload --upload-port <当前串口>
# 独立电机台架准备好后才选择下面的控制环境，不在RS3总线上使用：
.\.venv\Scripts\pio.exe run -e motor_control -t upload --upload-port <当前串口>
```

本轮没有运行任何 upload。上板性能、接收队列积压、UART新增状态行对满负载吞吐的影响尚待实测；出现丢帧/总线错误请保留原件，A/B 会话会被失效处理。软件只能响应可观察到的重启/阶段/数据边界，不能保证识别 FM03 自身的每一次快速重启；实际位置、坐标量纲与电机重启后的保留性仍未知。
