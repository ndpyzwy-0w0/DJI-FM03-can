# 测试台架接线（2026-10-08 更新）

**本文件记录"当前是怎么接的"，不是建议改线。** 带 ❓ 的是本 agent 尚未确认的，不得当作已知事实。

## 用户确认（重要，纠正本 agent 此前的误解）

- **跟焦电机只在需要抓包时才会连接到单片机（ESP32）上。**
- **CAN 收发器只在要做手动抓包时才接入设备。**
- 也就是说：**平时电机与 ESP32 不相连**；抓包时把电机的 C 口接到 ESP32 的收发器上取 D+/D− 差分信号。
- FM03 由 RS3 经该 C 口取电（5V）并传信号；另有一次是用**普通电源适配器经同一测试板**给 FM03 单独供电（当时 RS3 未上电）。

## 已确认清单

| 项 | 内容 |
|---|---|
| 被测链路 | RS3 ↔ FM03（跟焦电机）之间的原装 Type-C 线 |
| 取电/传信号 | FM03 由 RS3 经该 C 口取电（5V）并传信号 |
| 测试点 | 一个 **Type-C pinout 测试板**串在该 C 口上；监听 **D+/D−** 两线 |
| 监听的物理量 | D+/D− 差分信号，已证实有差分信号特征 |
| 电机↔单片机 | **仅在抓包/主动测试时**连接；平时不连 |
| 收发器↔设备 | **仅在抓包/主动测试时**接入；平时不接 |
| ESP32 侧 | ESP32-S3 + SN65HVD230，TWAI **Listen Only**，1 Mbps，采集经 USB-UART 921600 |
| 监听模块终端 | 模块上的 120Ω 已拆（总线两端 RS3/FM03 各 120Ω，实测≈60Ω，避免加第三终端） |

## 主动测试（M5）的接线含义

按用户的说明，**主动测试与抓包走同一套物理连接**，只是 ESP32 从 Listen Only 切到 NORMAL 才能发送：

- **电机侧**：电机的 Type-C（经测试板）→ ESP32 收发器的 CANH/CANL；电机另需 5V 供电。
- **RS3**：主动测试时**应不参与同一总线**，避免双主控争用。因此优先用**适配器经测试板**给电机单独供电（用户此前做过一次）；若必须用 RS3 供 5V，则需确认 RS3 的数据线不与电机数据线并接。
- **模式**：ESP32 需长按 BOOT 键 2 秒从 listen 切到 transmit（固件已支持）。

## 仍未确认（❓）

1. ❓ **主动测试时 FM03 的 5V 从哪里来、RS3 处于什么状态。** 适配器单独供电那次能否重复，尚未确认。
   - 注意：VBUS/GND 供电与 D+/D− 数据是**两回事**；只要能单独供 5V 且不让 RS3 的数据线入总线，就没有双主控风险。
2. ❓ ESP32 收发器的 CANH/CANL 是否直接接测试板的 D+/D−（用户描述指向"是"，但未逐线核对）。
3. ❓ D+/D− 上的信号**是不是 CAN**：未做位速率/差分幅度的直接测量。支持"是 CAN"的证据很强（CAN 控制器在 1 Mbps 能持续解出合法帧、`rx_missed`/`rx_overrun` 长期为 0），但**未直接证实**。

## 安全约束（不变）

- 绝不在 RS3 正在与电机正常通讯的总线上发送。
- 每个"开始发送"的子阶段都需要用户新的明确授权。
- 发送前必须先完成 M4：发送器在**完全脱离 RS3/FM03 总线**的条件下回环自检通过。
