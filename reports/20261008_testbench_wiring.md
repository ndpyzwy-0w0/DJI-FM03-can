# 测试台架接线（2026-10-08 更新）

**本文件记录"当前是怎么接的"，不是建议改线。** 带 ❓ 的是本 agent 尚未确认的，不得当作已知事实。

## 用户确认（重要，纠正本 agent 此前的误解）

- **跟焦电机只在需要抓包时才会连接到单片机（ESP32）上。**
- **CAN 收发器只在要做手动抓包时才接入设备。**
- 也就是说：**平时电机与 ESP32 不相连**；抓包时把电机的 C 口接到 ESP32 的收发器上取 D+/D− 差分信号。
- FM03 由 RS3 经该 C 口取电（5V）并传信号；另有一次是用**普通电源适配器经同一测试板**给 FM03 单独供电（当时 RS3 未上电）。

## 已确认清单

| 项 | 内容 |
|---|---|
| 被测链路 | RS3 ↔ FM03（跟焦电机）之间的原装 Type-C 线 |
| 取电/传信号 | FM03 由 RS3 经该 C 口取电（5V）并传信号 |
| 测试点 | 一个 **Type-C pinout 测试板**串在该 C 口上；监听 **D+/D−** 两线 |
| 监听的物理量 | D+/D− 差分信号，已证实有差分信号特征 |
| 电机↔单片机 | **仅在抓包/主动测试时**连接；平时不连 |
| 收发器↔设备 | **仅在抓包/主动测试时**接入；平时不接 |
| ESP32 侧 | ESP32-S3 + SN65HVD230，TWAI **Listen Only**，1 Mbps，采集经 USB-UART 921600 |
| 监听模块终端 | 模块上的 120Ω 已拆（总线两端 RS3/FM03 各 120Ω，实测≈60Ω，避免加第三终端） |

## 主动测试（M5）的接线含义 —— 已确认

**用户确认：主动测试时用适配器经测试板单独给电机供 5V。**（RS3 不参与。）

因此 M5 的台架配置是：

| 项 | 配置 |
|---|---|
| 总线上的节点 | **只有 FM03（跟焦电机）** |
| FM03 供电 | **电源适配器经 Type-C 测试板给 5V**（VBUS/GND） |
| FM03 数据 | 测试板的 D+/D− → ESP32 收发器的 CANH/CANL |
| RS3 | **完全不参与**（断电、数据线不入总线） |
| ESP32 | 固件切到 `loopback_test`（先自检）或 NORMAL 模式；收发器 CANH/CANL 接测试板 |
| 终端电阻 | 监听模块的 120Ω 已拆；此配置下总线上**只有 FM03 自带的一个 120Ω**（单端终端；短线排线通常可用，但非标准双端） |
| 双主控风险 | **不存在**——总线上只有 FM03 一个节点加一个发送器 |

**这就是 M5 的隔离台架**：无 RS3、无其他主节点。所有"开始发送"的子阶段仍**各需用户新的明确授权**。

## 两个收发器模块的分工（用户确认）

用户有**两个 SN65HVD230 模块**，靠**手动插拔杜邦线**切换：

| 模块 | 120Ω | 用途 |
|---|---|---|
| 模块 A | **无**（已拆） | **任何时候的纯监听**——避免在已双端终端的总线上加第三终端（总线两端 RS3/FM03 各 120Ω≈60Ω） |
| 模块 B | **有**（保留） | 主动测试用；与 FM03 自带的 120Ω 并联 = **标准 60Ω** |

- **不需要改动任何模块**：M5 场景（总线上只有单独供电的 FM03）用模块 B 反而得到标准双端终端。
- **两个模块绝不能同时接在总线上**（会成 40Ω）。
- **绝不能用 `loopback_test` 固件配接在真实总线上的收发器**——该固件要自己发自己收，总线必须空着。

## M4 回环自检：不需要短接任何杜邦线

- SN65HVD230 **内部就把 TX 回送到 RX**，而控制器的 RX 同时反映"收发器正在驱动什么"与"总线在传什么"。因此控制器设为 `NO_ACK` + 自发自收时，**会收到自己发的帧**，无需在模块的 D 与 R 之间加跳线。
- 唯一要求：**总线是空的**——不接电机、不接 RS3、不接其他节点。用哪个模块都行（模块 B 的 120Ω 在空总线上无害）。

## 仍需注意（不是阻塞项）

- 适配器的**电流能力**要足够驱动电机（未测量）。
- 只有电机供电时，它是否进入比"红灯常亮"更接近正常的状态**未知**——这正是 M3/M5 要测的。
- `D+/D−` 上的信号**是否就是 CAN** 仍未直接测量（位速率/差分幅度）；但 CAN 控制器能在 1 Mbps 持续解出合法帧，支持"是 CAN"。若 M5 发送后毫无反应，这个假设应优先复核。

## 仍未确认（❓，不阻塞 M4）

1. ❓ ESP32 收发器的 CANH/CANL 是否就是接测试板的 D+/D−（用户描述指向"是"，未逐线核对）。
2. ❓ `D+/D−` 是否为 CAN（同上）。

## 安全约束（不变）

- 绝不在 RS3 正在与电机正常通讯的总线上发送。
- 每个"开始发送"的子阶段都需要用户新的明确授权。
- 发送前必须先完成 M4：发送器在**完全脱离 RS3/FM03 总线**的条件下回环自检通过。
