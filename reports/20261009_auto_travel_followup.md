# 自动识别行程新增信息能支持什么

分析时间：2026-10-09 01:09:49 北京时间。证据为最新自动识别抓包、九份历史记录及用户新确认；当前main，纯离线，不改变监听固件、不打开串口、不发CAN。

## 可以直接开展的功能

**被动校准状态观察。** 已能用双CRC有效的`0x504 BF→E5 flags00 04:2F`、15字节payload、`09 00`前缀，读payload偏移2及3..6的int32LE。上位机可以显示原始阶段0/1/2/3、阶段经过时间及结果3757，记录结果变化。1/2可标“识别阶段候选”，3+有限数值可标“结果已出现候选”；不能把0定义为未校准、3定义为成功或给3757加角度/圈/毫米单位。约100ms周期适合过程观察；超时应显示数据过期，不能沿用旧值当实时。

**自动识别流程的独立控制准备。** `04:2F`载荷`02 00 01`是目前最强启动候选，16字节、CAN两帧8+8。若隔离台架验证有效，可以替换现在sweep依赖人工触限/STOP的寻限位方式，复用原电机已有“触限→回退→复触、再处理另一端”的流程。此能力尚未实现或主动验证；已经拿到的是报文入口及观察反馈，不是已获得独立自动回零功能。

**识别结果验证。** 用3757及其后续变化判断这个字段更像固定行程参数、端点坐标、目标位置还是当前坐标。这是后续位置功能的入口，但一个有限值还不足以得到两个限位坐标、当前角度或绝对定位命令。

## 用户新确认对协议理解的影响

用户原话：“电机往一个方向旋转，到达物理限位后停止，往回退一小段，再撞一次物理限位然后去找下一端，行程两端都是这个流程”。实际流程可表达为：

```text
寻找端A → 触限停止 → 回退 → 再触端A
       → 寻找端B → 触限停止 → 回退 → 再触端B
```

这证明该次有实际运动与回退/再次接触，补充了此前仅有报文状态的证据。方向、退让量、各步时刻和RS3界面成功提示仍未知。重复接近可能用于稳定端点或减少间隙影响，这是解释假设；尚未证明编码器、电流检测、扭矩阈值或具体堵转检测机制。

**09状态1/2更像过程阶段，不能直接当通用堵转报警。** 同一端包含初次触限、回退和再次触限多步；217条09状态中只出现0→1→2→3三个转移，没有额外的子步枚举或随运动变化的数值。第一段状态1到2首观察间隔1.800028秒，第二段2到3为6.618122秒；与两端处理阶段相容，但没有物理同步标记，不能把两个间隔直接当两端距离、运动时间或每次触限时间。

**现有速度STOP不能作为校准中止保证。** 用户确认电机运动，同时两路04:69在整段中持续为0；归零并未阻止这次内部流程发生。现有motor_control的watchdog/STOP只撤销速度指令，不应宣传为能中止这种内部自动流程。真正尝试启动候选之前，需要单独查明中止/退出方法，不能猜`02 00 00`就是停止。也不能把校准和非零速度同时发送后的优先级当成已知。

## 对3757的进一步排查

本次09阶段0/1/2的四字节都是`FF FF FF 7F`；阶段3才是`AD 0E 00 00`，之后84包/8.300151秒没有变化。当前有以下互相未区分的解释：

- 行程长度/学习出的范围参数；
- 某一端点的编码坐标；
- 校准结束后的目标位置或当前位置；
- 其他校准结果量。

**不能靠历史极值的正负，把这字段解作速度或旋转方向。** 对09采样匹配同可靠段内最近50ms的0x503拨轮值，历史慢速反转记录有124次拨轮值为正、09字段却始终为INT_MIN；慢速正转记录151次拨轮值为负也同样INT_MIN。两个符号都可伴随同一个极值。这否定了“该字段符号直接等于当前速度方向”的简单解释，但并未确定真实语义。

**当前还没有两个端点或连续位置字段。** 12/18/19/1B保持已知固定载荷；13的1/2/3周期及后部全FF也是历史既有模式，未发现与本次回退/复触对应的新值。04:05的四个float32仍具有单位四维向量特征，1082包中模长平方误差最大约2e-07，另有约20ms递增的计数；没有由此取得新的电机角度/行程单位解码。

## 状态路由与去重已经核实

选取BF→52的09/12/13状态组：0x504与0x232有650对逐字节全同包；0x232/BF与0x201/DF有650对，载荷、序号、命令相同，仅源地址和CRC改写。它们是相同逻辑信息的复制表现，不能算三次独立反馈。显示时选一路09即可；复制关联以载荷/序号/命令为据，不据此推断物理转发拓扑。

## 本轮解析修正及影响

上轮计10420包、28个truncated；独立按完整帧长度+CRC复核证明其中漏掉13个有效04:05包。原重组器在遇到以55开头、长度貌似合理的续片时提前截断，失败后还可能越过后续真实首片。

已修正共享`tools/analyze_protocol.py`：包首检查CRC8，续片不靠55中止，按声明长度组包后校验CRC16，失败后从下一整帧重试。新增自检覆盖无效/有效CRC8的55续片、截断恢复及坏CRC后恢复；不扫描帧内字节、不跨序号缺口/重启/丢帧计数变化重组。

本次重算**10433双CRC有效包、1个truncated、3个not_a_packet_start**；新增13个全为04:05。十份证据对比共多接受92个04:05包，旧接受包无一丢失。校准候选启动包、09阶段与时间、3757以及04:69零值统计逐项与修正前一致，未找到额外的控制/取消报文。末尾40字节及首行异常仍原样保留，不能宣称绝对无损。

复核数据：`reports/20261009_reassembly_fix_audit.json`；继续分析及方向配对、四维向量、复制证据均进入`reports/20261009_auto_travel_analysis.json`。旧历史报告的解析计数属于当时结果，不整体覆写；使用当前机器报告和审计进行新比较。
