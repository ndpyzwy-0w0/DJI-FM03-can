# RS3 控制流 vs 我们现在能做的（2026-10-08）

全部结论来自**已有抓包**的离线测量（7 份，2026-10-07，含静止/慢快正反转/单次拨动/归零）。
分析助手写在被忽略的 `.pio/` 下，未入库。**本轮没有发送任何 CAN 帧。**

## 一、RS3 实际在下发什么

以 `E5>BF 04:69`（CAN `0x503`）与 `E5>52 04:69`（CAN `0x201`）为唯一拨轮命令流：

| 项 | 实测值 | 依据 |
|---|---|---|
| **周期** | **10.0 ms/包/路由**（约 100 包/秒/路由；两路交替 ⇒ 总线上约 5 ms 一次） | 同路由帧间隔中位 `10002 µs`，min 7895 / max 30927（抖动来自采集丢帧） |
| **数值语义** | **带符号速度**（已由本项目在板实验确认） | 非零值持续发送⇒持续转动；零值⇒停 |
| **数值更新率** | 运动时**几乎每个包都在变**（慢正转 76% 的相邻包数值不同；变化幅度中位 −1、范围 −69..+86） | 数值变更统计 |
| **静止时** | 数值**恒为 0**、从不变化 | 静止段 1037×2 包全 0，变更 0 次 |
| **序号** | **两路由共享一个递增计数器**：同路由步进恒为 `2`（偶发 `4`），即两路交替各取 +1 | 路线内步进集合 `[2, 4]` |
| **路由** | **双路由**：`0x503`→BF 与 `0x201`→52，载荷完全相同 | 两路包数几乎相等、数值序列一致 |

### 一个关键观察

`20261007_201035`（单次拨动后停手）里数值的**上升**过程被完整抓到：

```
5290.5  -45      5380.5  -462     5470.6   -994
5300.5  -143     5390.5  -477     5480.6  -1114
5310.5  -175     5400.6  -577     5490.6  -1177
5360.5  -289     5450.6  -785     5500.6  -1230
5370.6  -380     5460.6  -867     5510.6  -1240   ← 峰值
```

**约 220 ms 内从 −45 单调升到 −1240（峰值），随后回落。** 这说明 RS3 下发的不是
"跳到一个速度然后保持"，而是**一条随时间连续变化的数值曲线**：手拧得越深越快，
松手回中后数值回落。**电机是被这条曲线"喂"着走的**，所以数值必须持续更新。

### 必须说明的证据边界

这些抓包在刷屏工况下**丢了大量帧**（`logger_dropped` 长期增长），所以
①上述曲线是**欠采样**的，采样率约 10 Hz/路由，快速变化段不可逐点还原；
②"每包都变"也可能部分是丢帧造成的跳变。**故只可断言"数值在持续更新、存在单调上升段"，
不可断言精确波形。** 要精确还原需要不丢帧的记录（本机 UART 在刷屏下会丢，属已知限制）。

## 二、逐项对比

| 维度 | RS3（实测） | 我们的固件 | 影响 |
|---|---|---|---|
| 命令流 | `04:69` E5→BF/52 | 同一条，同载荷格式 | 一致 |
| 数值语义 | 带符号速度 | 同 | 一致（已实测） |
| 非零值行为 | 一直转，直到数值回 0 | 同 | 一致（已实测） |
| 位置语义 | 增量累积，无绝对基准 | 同 | 一致（已实测） |
| **更新周期** | **10 ms/路由（≈100 Hz）** | **50 ms（20 Hz）** | **慢 5 倍**；改 `interval` 可对齐（固件支持 10..1000ms） |
| **数值模式** | **持续变化的曲线**（手拧深度→速度） | **hold 固定值**；新增 `pulse` 做脉冲串 | **这是最大差别** |
| 路由 | 双路由（0x503+0x201） | 单路由（0x503） | 双路由曾用于二分对照，只是重复发送，非功能差异 |
| 序号 | 两路共享递增（同路 +2） | 恒 0 | 需求未验证；实验证明恒 0 也能正常驱动 |
| 电机回报 | `04:2F` 家族仅 2–5 个离散常量 + 心跳 | 我方不解析（`logrx` 默认关） | 无位置反馈可用（已单独查证） |

## 三、结论

**能对齐的**：命令内容、速度语义、方向、停止行为、路由格式——已经一致。
**没对齐的两点**：
1. **更新率**：我们 50ms，RS3 10ms。固件已支持改 `interval 10`，**建议先试这个**（零风险）。
2. **数值模式**：RS3 是"实时曲线"，我们是"固定值"。对人的操作体验来说，
   固定值其实更好用（按一下就一直转）；但**若要复刻 RS3 的手感**（拧多深转多快、松手减速），
   需要上位机**持续下发变化的数值**。`pulse` 是朝这个方向的第一步（短脉冲串）。

**仍然没有的**：绝对定位。RS3 也没有——它同样是速度流 + 无位置回报。

## 四、下一步可选项

- **对齐更新率**：`interval 10` 再看行为是否更接近 RS3（最简单，先做这个）。
- **复刻曲线**：上位机加一个"按时间曲线发数值"的模式（如线性 ramp、正弦摆动），
  用于测"电机是否跟随数值变化"以及跟随延迟。
- **测跟随延迟**：用 `pulse` 缩短 hold（100ms→50ms→20ms），找**最小可产生位移的脉冲**，
  那就是这个闭环的时间分辨率。
