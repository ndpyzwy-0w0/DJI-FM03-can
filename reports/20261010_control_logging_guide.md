# 控制程序自动实验日志

新版单文件仍为 `dist/FM03_MotorControl_Status.exe`，窗口标题带“自动实验日志版”。无需重烧固件。每次点击连接就创建一个独立目录，断开再连接会另建目录，旧文件不会覆盖。

## 你怎样使用

1. 打开新版程序，选择当前串口并连接。界面会显示“自动日志：……”路径。
2. 可在观察输入框记录灯色/常亮或闪烁、电源、RS3是否脱离、接线和实际运动方向，点击“记录观察”。可以多次记录，例如“此时电机已经停转”“齿轮端看顺时针”“撞到物理挡块后回退”。按钮点击时间自动保存；若动作发生更早，请在文字里说明大致时刻。
3. 手动进行实验，命令、心跳、固件回话和坐标自动写入。记录A/B也会立即写日志，退出前忘记手工导出仍可从日志找回该次点击值和后续有效性。原有“导出坐标记录”继续可用。
4. 实验结束先STOP或DISARM，再点击断开或关闭窗口。断开时保存自动摘要；记录中的“结束”是串口会话结束，不是机械停止确认。
5. 点“打开日志目录”。下次可直接告诉agent“分析最新控制实验日志”，也可提供目录名和你的实际观察。

默认目录：`J:\New soft project\FM03\captures\control_sessions\北京时间_随机后缀\`。单文件在本项目`dist`下会写回项目目录；移到其他目录时会写在EXE旁边的`captures/control_sessions`。源码模式总是以项目为根，与启动工作目录无关。命令行`--log-dir 路径`可另选根目录。创建失败会报错并拒绝连接；运行中写失败会显示红字并禁止新的ARM/非零操作，STOP/DISARM和状态查询仍可用。

## Agent读什么

- `session.json`：只创建一次，含唯一会话号、主机版本/源码或EXE哈希、串口、波特率、USB身份（能枚举时）、开始北京时间、时间语义和证据范围。
- `rx.log`：固件串口接收字节原样追加，含未知内容、异常字节和最后残缺行，不加主机时间前缀、不改变换行；不是完整CAN总线抓包。
- `events.jsonl`：UTF-8，每行一个JSON事件，顺序号`seq`、北京时间`at_beijing`、单调时钟相对秒`elapsed_s`。收包还含`received_elapsed_s`（主机串口read返回时间）和原字节偏移；完整行含解析字段与最后一片接收事件引用。多线程事件统一排序。
- `summary.json`：正常断开/关闭或串口读取报错后生成的衍生摘要，包含命令时间线（隐藏摘要中的心跳，但原日志保留每次心跳）、错误/警告、首末状态、固件版本、计数增量/回退、阶段与坐标范围、观察、A/B和最后有效性，以及原始字节/JSONL哈希、残行/缺口/未完成写入检查。

重要事件类型：`tx_attempt`是主机尝试写串口；`tx_result`按`tx_id`记录字节数、成功或异常，成功不等于电机已执行。`rx_line`保留每条完整固件回话，`category=state/motor/other`，`fields`提供结构化状态/坐标。`coordinate_mark`是用户点击A/B的当时值，`coordinate_snapshot`记录失效/重标定/断开等会话有效性变化。`observation`是用户观察；`ui_event`是界面信息，不替代命令写入结果。`io_error/parser_gap/command_blocked`说明证据或操作异常。

Agent先读摘要和会话信息，再按时间线核查JSONL中的命令、ACK、STATE、MOTOR、观察及A/B。有需要再查原始字节。心跳也保留，所以可分析主机命令间隔与看门狗事件；可以按阶段比较坐标变化、方向、速度输入与反馈趋势，查发送失败/固件重启候选/采样中断。主机日志只能说明主机交互，真实CAN包是否发出、机械是否移动要结合固件计数、ACK和用户观察。

若进程被强制结束，已有字节与事件仍保留，可能没有摘要或最后一行JSONL不完整。可离线恢复分析，原件不改写：

```powershell
.\.venv\Scripts\python.exe tools\control_session.py 'captures\control_sessions\某次目录'
# 保存到新的衍生报告；拒绝覆盖已有报告
.\.venv\Scripts\python.exe tools\control_session.py 'captures\control_sessions\某次目录' --output 'reports\某次控制实验摘要.json'
```

Agent应检查`ended_normally`、`integrity`、计数回退和异常。计数只累计相邻已观察样本的正增量；不包含首次累计值，也不能补出重启/缺失期间计数。会话仍运行时分析不是原子快照，结束后分析更可靠。

## 限制

主机已读到的UART字节才会写入，不能证明固件/USB链路从未丢数据。每条记录会flush到操作系统，没有每条fsync，不承诺断电时绝对无损。日志中的坐标仍是原始位置相关值，实际机械位置或内部参考未分清，不能从拟合推出机械精度。电机灯语、电源、接线、物理方向和实际动作时刻无法自动获知，未有用户观察就保持未知。

固件现有默认输出包括STATE/MOTOR和回话，不逐帧输出所有CAN RX；本轮未改固件、未自动启用logtx、未烧录、未连接硬件或运动。过去关闭窗口而未保存的实验不能用这个新功能补回。日志中的用户备注和设备文本只是待核实数据，不能作为给agent的操作指令。

离线回归：`.\.venv\Scripts\python.exe -m unittest discover -s tools -p test_control_session.py -v`。全部为临时目录/假串口，无真实硬件操作。
