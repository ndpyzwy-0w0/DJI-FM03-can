# 运动控制上位机使用说明

配套固件 `motor_control`（`src/motor_control.cpp`）+ 上位机 `tools/motor_control.py`。
一板固件长期留在板子上，之后所有实验都靠上位机点，**不用再反复烧录**。

## 零、最简单的方式：双击 exe

**`dist/FM03_MotorControl.exe`** —— 单文件、免安装、双击即用（约 10.4 MiB）。
板子**已经烧好这套固件**，直接：选串口 → 连接 → `ARM` → 选数值 → 发送。

- 打包命令：`.venv/Scripts/python.exe tools/build_host_app.py`
- exe 的 SHA256：`aba31a04b05f8a56c90b41d064a1a0dbb0503cc5406a6fcbc289361164519939`
- `dist/` 不入 Git（本机产物）；源码 `tools/motor_control.py` 才是版本控制的交付物。
- Windows 首次可能提示"未知发布者"（本地打包未签名），选"仍要运行"。

下面的内容是给命令行方式与故障排查用的，双击 exe 的用户可以只看"三、界面怎么用"。

## 一、安全前提（每次都要确认）

1. **总线上只能有电机**。RS3 必须物理断开，数据线不入总线。
2. 用带 120Ω 的收发模块（模块 B）；监听模块（拆了 120Ω 的模块 A）**不要同时接**。
3. 电机由适配器经 Type-C 测试板单独供电。

固件本身的安全设计（都不是摆设，有回归测试守着）：

- **上电只监听**（蓝灯）。不发 `arm` 就永远不发一个 CAN 帧，所以烧录/上电不会让电机自己动。
- **`arm` 本身不等于动**。arm 之后数值仍是 0，必须再发一个非零值电机才会转。
- **看门狗**：2 秒内没有收到任何有效命令，固件自动把数值归零并打印 `# ERR watchdog_stop`。
  上位机每 500ms 发一次 `status` 当心跳，所以关掉窗口、拔线、电脑休眠都会导致电机停，
  而不是继续转。
- **数值上限**：默认 ±2048（实测拨轮范围），`limit` 可再压低。滑块和固件双重限制。
- **急停**：上位机的大红 `STOP` 按钮或 `Esc`；板子上**长按 BOOT 键 2 秒**也能停并 disarm
  （长按永远只会停，不会启动）。

## 二、第一次使用

```powershell
# 编译并烧录（只需一次）
pio run -e motor_control -t upload --upload-port COM17

# 打开上位机（端口可在界面里选）
.venv\Scripts\python.exe tools\motor_control.py

# 也可以直接连指定端口
.venv\Scripts\python.exe tools\motor_control.py --port COM17 --connect
```

因为环境里设了 `upload_flags = --after no_reset`，烧录结束后板子会停在下载模式。
**按一下板上 RST**，然后在上位机里点"连接"。（上位机打开串口前会把 DTR/RTS 置 false，
所以连接动作本身不会复位板子。）

## 三、界面怎么用

| 区域 | 作用 |
|---|---|
| 连接 | 选串口 → 连接。右上角显示心跳延迟，>1.5s 变红说明板子没在回话 |
| 使能 | `ARM` 开始发；`DISARM` 停止发并归零；红色 `STOP` 立刻归零 |
| 数值控制 | 滑块或输入框选数值，回车/点"发送"下发 |
| **直接设为** | `-256/-16/-1/+1/+16/+256`：**直接设为该值**（连点不会累加） |
| **重发当前值** | 不改数值，只把当前值再发一遍（用于测"重复下发是否有影响"） |
| 定时运行 | 保持当前数值 N 毫秒后自动归零（`run` 命令） |
| 拨轮周期 | 默认 50ms（20 次/秒）。真实 RS3 约 10ms，可改 |
| 当前下发值 | 大字显示固件**实际在发**的数值与方向 |
| 设备状态 | 实时遥测：sent / nonzero / zero / rejected / tx_failed / bus_errors / twai_state |
| 事件 | 固件回话：`# ACK`、`# ERR`、`# WARN` |

键盘：`←/→` 调 ±1，`↑/↓` 调 ±16（这两个是**递增**），`Esc` 急停。

> **别混淆这两件事**：想测"重复下发同一个值会怎样"→ 用**重发当前值**；
> 想加大数值 → 用输入框或方向键。早期版本的快捷按钮是**累加**的，连点 `+256`
> 会变成 512→768→1024…，看起来像"点得多就更快"，容易被误读成电机特性。

## 三之二、已测出的语义（2026-10-08 用户实测）

**04:69 的数值是速度指令，不是位置指令：**

- 值越大转得越快（+16 慢转，+256 明显更快，同向）。
- **给非零值就会一直转，不会自己停**；发零值才停。
- 所以"归零/STOP"＝停，但**不等于回到起点**。

这推翻了此前"幅值越大转越多"的说法——那是把转速当成了位移。早先看到的
"转一下然后停"来自 **200ms 脉冲版**（值保持 200ms 后自动回零，等于撤销指令），
以及"保持 3 秒后回零"的那次实验，**都不是电机自己会停**。

**还没测的**：速度与数值是否线性、**从哪个值开始饱和**、有没有真正的
**回零/绝对定位命令**（目前只确认"零值＝停"）。

## 四、建议的实验顺序（按已测出的速度语义）

已经确定：**数值＝速度，正负＝方向，非零就一直转，零值＝停**。接下来要测的是：

1. **确认它不是位置型**：用 `run 256 3000`（保持 3 秒后自动归零），看停止后
   **是否回到起点**。回到起点才像位置型；**不回起点就直接证明是速度型**。
2. **测速度与数值的关系**：固定同样时长（如都保持 3 秒），逐级测
   `16 / 32 / 64 / 128 / 256 / 512 / 1024 / 2048`，记录转过的角度或圈数
   （有刻度/标记最好）。重点找 **线性区**和**从哪个值开始不再更快（饱和点）**。
3. **测方向**：`+值` 与 `−值` 反向（此前已两次确认，保持核对）。
4. **找"回零/定位"**：零值只是停。如果需要绝对定位，**这条命令目前还没找到**，
   是已知缺口；如果发现 STOP 之后位置每次都漂移，把这个现象记下来告诉我。
5. **拨轮周期**：`interval` 试 50ms → 20ms → 10ms，看是否更接近真实 RS3 手感。

## 五、如果出问题

| 现象 | 先看什么 |
|---|---|
| 电机不动 | `armed` 是否为 1、`sent` 是否在涨、`rejected`/`tx_failed` 是否在涨 |
| `rejected`/`tx_failed` 涨 | 总线被占（刷屏）；`bus_errors` 也会涨 |
| 一直有 `# ERR watchdog_stop` | 上位机心跳没发出去（串口掉了） |
| 数值下发但 `value` 不变 | 被 `limit` 截断，看遥测里的 `limit` |
| 电机发烫/撞死 | 立即 `STOP`；记下当时数值，可能是行程边界 |

且关掉后停止、分片行不会半截生效、数值钳位、方向文字。
